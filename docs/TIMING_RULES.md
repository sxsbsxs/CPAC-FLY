# 计时与测量规范

## 时间基准

使用相机帧提供的采集时间戳或可验证的媒体时间线。记录原始时间戳、时间基准、帧间隔和异常。不要用 UI 时钟或处理完成时间作为飞行时间。高度序列、下降率和预测必须沿用同一采集时间基准。

## 拍摄模式与计时

首版必须区分两种拍摄模式，但两者均以原始视频时间线/帧呈现时间戳为唯一计时基准：

- 固定机位：使用目标在图像坐标中的连续运动提出出手候选；地面区域需事先标定，落地候选必须结合持续低运动与接触地面证据。
- 手持跟拍：先估计背景/相机全局运动，再从目标运动中扣除相机运动；未经运动补偿的目标位移不能直接当作飞机速度或出手证据。补偿质量不足时必须标记需要人工复核。
- 两种模式都要保存视频帧时间戳、模式、候选事件置信度和复核状态。慢放逐帧校正可以修正候选事件，但不能覆盖原始自动结果。
- 目标框选/点选只用于指定追踪对象，不得直接触发计时起止。
- 当前 FlightTimingAnalyzer 是纯 Kotlin 候选事件算法骨架；真实纸飞机检测、手持相机运动估计、地面接触识别和视频回放复核尚未接通。

## 事件定义

赛事计时的开始/结束事件必须按目标赛事规则配置。一般训练场景可以提供“出手”和“首次触地/规则终止事件”的候选标记，但不能把某一通用定义冒充所有比赛规则。

## 高度定义与测量质量

- “离地高度”定义为飞机选定参考点相对于局部地面参考平面的垂直距离，单位 m。
- 相机到飞机的直线距离是斜距，不等同于离地高度。
- 优先使用设备支持时的 ARCore Depth；结合相机内参、设备姿态、地面平面和深度有效性检查。
- 若无可靠地面参考、深度无效、飞机检测框混入背景或标定不足，不输出看似精确的米制高度；可显示相对高度趋势和“需要标定”状态。
- 高度样本至少保存：采集时间戳、估计高度/相对值、测量来源、置信度、有效深度比例、地面参考/标定版本、算法版本。

## 下降率与剩余时间

- 下降率定义为高度对时间的负导数，正值表示下降，单位 m/s。
- 以时间戳而非帧数求导；采用滑动窗口鲁棒线性拟合/滤波，避免简单相邻帧差分放大噪声。
- 保存原始高度、滤波高度、窗口长度、下降率和不确定度，便于审计。
- 只有飞机处于持续下降、下降率足够稳定且落地/终止定义明确时，才给出剩余时间估计。
- 剩余时间用当前高度与近期下降趋势估算，并结合历史飞行阶段/终止事件模型；显示区间和置信等级，而不是单一伪精确数字。
- 上升、盘旋、下降率接近零、数据陈旧、目标丢失、深度质量差或飞行轨迹明显改变时，暂停预测并解释原因。
- 预测值与实际终止时间对比，持续记录偏差；不可将预测当作官方成绩。

## 事件与算法结果

检测模型只提出候选事件。每个候选事件保存：
- 事件类型
- 时间戳/媒体时间
- 置信度
- 证据帧引用
- 是否由用户修正
- 修正前后值与修改时间

## 异常情况

以下情况必须提示不确定性或要求人工复核：
- 飞机飞出画面
- 遮挡或与背景混淆
- 起飞/触地瞬间漏帧
- 可变帧率或时间戳异常
- 视频暂停、剪辑、转码或丢帧
- 无法区分触地与掠过障碍物
- 深度图缺失、深度与视频帧不同步、地面参考面不可靠
- 相机移动、变焦或自动切换镜头导致标定失效

## 结果标签

- 自动估算
- 用户复核
- 官方确认

不得仅凭普通单目视频推算真实三维位置、真实三维速度、升力或阻力。二维轨迹必须标注为图像平面轨迹。
